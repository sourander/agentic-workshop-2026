# Deploy on CSC Rahti

Rahti is an OKD (Kubernetes) based platform for running containerized applications. This guide will help you deploy the workshop infrastructure on Rahti.

## Prerequisites

You need the following tools installed:

- `oc` — OpenShift CLI ([install guide](https://docs.okd.io/latest/cli_reference/openshift_cli/getting-started-cli.html))
- `docker` — for building and pushing images
- `just` — task runner ([install guide](https://just.systems/man/en/installation.html))
- `envsubst` — usually pre-installed on macOS/Linux (part of `gettext`)
- `uv` — Python script runner ([install guide](https://docs.astral.sh/uv/getting-started/installation/))
- `mc` — MinIO client ([install guide](https://docs.min.io/docs/minio-client-quickstart-guide.html))

## First Steps

Quick things to do first:

1. Create a project in CSC that has Rahti service enabled.
2. Login to `https://rahti.csc.fi/` console.
3. Choose *"Copy login command"* from the top right corner and run the command in your terminal. It will look something like this:
   ```bash
   # Login
   oc login \
   --token=sha256 \
   --server=https://api.2.rahti.csc.fi:6443
    ```
4. Create a new project, fill in the project number from My CSC:
   ```bash
   # Create a new project
   oc new-project \
   aika-agent-workshop \
   --description='csc_project: 201xxxx'

    # This command should now return the project name
    oc project
   ```
5. Login to image registry:
   ```bash
   docker login -p $(oc whoami -t ) -u unused image-registry.apps.2.rahti.csc.fi
   ```

## Deploying the Custom Images

Mattermost's official image runs as root by default, which is not allowed on OKD. The `mattermost.Dockerfile` builds a modified image that adjusts file permissions so it can run as an arbitrary non-root user.

Build the image:

```bash
just build
```

> **Note for Apple Silicon (M1/M2/M3) users**: The Mattermost image is only available for `linux/amd64`. The Dockerfile already specifies `--platform=linux/amd64` in the `FROM` line, so Docker Desktop will use Rosetta emulation automatically. Make sure **Rosetta** is enabled in Docker Desktop under *Settings > General > "Use Rosetta for x86_64/amd64 emulation on Apple Silicon"*.

Push it to CSC's image registry:

```bash
just push
```

Verify the image is available:

```bash
oc get imagestream
```

You should see `mattermost` listed with a `latest` tag.

## Deploying the Workshop Infrastructure

The deployment is split into two phases: first deploy the services internally (no public access), then expose routes after claiming admin accounts. This prevents bots or random visitors from creating the first admin user.

### 1. Create Secrets

Generate random passwords and create the `workshop-secrets` OpenShift secret:

```bash
just create-secrets
```

The generated credentials are saved locally to `.workshop-secrets.env` (git-ignored).

### 2. Deploy Services

This applies all Kubernetes resources (PVCs, deployments, services) **without** public routes:

```bash
just deploy
```

Wait for all pods to become ready:

```bash
just wait
```

Check status:

```bash
just status
```

### 3. Expose Public Routes

Once admin accounts are secured, make the services publicly accessible:

```bash
just expose
```

This prints the public URLs. They can also be accessed with `just status` or from CSC Rahti Console.

### 4. Create Workshop Users

To create n8n user accounts for workshop participants via the API, set your n8n API key (from Settings > n8n API -> Create an API Key in the n8n UI).

Add the values to the `.workshop-secrets.env` file. There are already empty placeholders for `N8N_API_KEY` and `N8N_BASE_URL` that you can fill in.

```bash
uv run scripts/create-users.py
```

### 5. Get Mattermost Invite Links

This is not a user-level invite link, but a global link. Thus, it can be simply generated from the site by pressing the `+` button, then "Invite People" and "Copy Invite Link". It will look something like this:

```
https://mattermost-aika-agent-workshop.2.rahtiapp.fi/signup_user_complete/?id=abd1234567890
```

This will create a `.this-session-members.json` file with the generated invite link for each generated user. Usernames are generated petnames (e.g. "happy-dolphin").

### 6. Create Minio Users

To do this, run in a terminal A:

```bash
just port-forward-minio
```

Then, open a new terminal session B and run:

```bash
just create-minio-users
```

This will read and modify the `.this-session-members.json` file that was generated by the `create-users.py` script (step 5), and create corresponding MinIO users. The password will be title cased email's local part + random 2-digit number (e.g. `happy-dolphin` -> `Happy-Dolphin42`). The schema is now:

```json
[
  {
    "email": "cosmic-oriole@foobar.local",
    "n8n_invitation_url": "https://n8n-aika-agent-workshop.2.rahtiapp.fi/signup?token=<really-long-token>",
    "minio_username": "cosmic-oriole",
    "minio_password": "Cosmic-Oriole95"
  }
]
```

## Configuration

The OKD project name defaults to `aika-agent-workshop`. Override it by setting the `PROJECT_NAME` environment variable:

```bash
export PROJECT_NAME=my-custom-name
just deploy
```

All `just` recipes use this variable to derive image paths and hostnames.

## Post-Workshop Cleanup

Delete all workshop resources (deployments, services, routes, PVCs, secrets):

```bash
just teardown
```

> **WARNING**: This permanently deletes all persistent data (n8n workflows, Mattermost messages, MinIO files, database contents).

Verify nothing is left:

```bash
oc get all,pvc,secret
```

To also delete the OKD project entirely:

```bash
oc delete project aika-agent-workshop
```
